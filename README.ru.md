# Из заметок встречи — в проверенный реестр задач

**Agent Workflow Kit** сверяет предложенные личные обязательства с точными
фрагментами заметок. После предоставленной проверки человеком он выгружает
принятые строки в локальный CSV: ответственный, задача, срок и цитата-основание.
Хеши указывают, по каким версиям входных файлов получен результат.

Совпадение цитаты подтверждает совпадение текста. Само по себе оно не доказывает
обязательство, согласованный срок, полноту списка или личность проверяющего.
В учебном примере вопрос про пятницу проходит техническую проверку, но человек
отклоняет его: это ещё не обещание выполнить задачу.

Python 3.9+, стандартная библиотека. Модуль работает локально, без модели,
аккаунта, API-ключа и покупки ядра. Он не извлекает задачи автоматически, не
получает запись встречи, не удостоверяет проверяющего, не отправляет сообщения
и не создаёт задачи в живой CRM. В пакете — один воспроизводимый процесс и
его локальные проверки.

## Повторите учебный пример

Распакуйте выпуск v0.1.0 в новую папку и выполните:

```bash
python3 -B workflow_kit.py --json doctor
python3 -B workflow_kit.py --json review examples/source.json examples/candidates.json
python3 -B workflow_kit.py --json export examples/source.json examples/candidates.json examples/decisions.json --output ./demo-tasks.csv
```

В проверке **пять кандидатов: три технически согласованы, два требуют разбора**.
Код завершения `review` — **1**, так и должно быть. Предоставленные решения
принимают два кандидата и отклоняют три. Поэтому `export` завершится с кодом
**0** и сохранит две задачи. Сопоставьте вывод с полученными в пакете
[JSON-проверкой](examples/review.json) и [CSV](examples/tasks.csv).

| Кандидат | Проверка фрагмента | Решение в учебном файле |
|---|---|---|
| A01: подготовить план к явно указанной дате | Согласовано | Принять |
| A02: сверить две суммы, без согласованного срока | Согласовано | Принять; срок оставить пустым |
| A03: выдуманная цитата при существующей строке | Цитата не совпала | Отклонить |
| A04: точная цитата приписана другому участнику | Ответственный не совпал с говорящим | Отклонить |
| A05: вопрос или предложение о пятнице | Согласовано | Отклонить: личного обязательства нет |

Заметки, предполагаемое извлечение и решения составлены для обучения. Это не
запись реальной встречи, не сохранённый ответ модели и не результат продаж.
Для шестой строки источника кандидата нет; полноту извлечения программа не
проверяет.

Предпросмотр без сохранения CSV:

```bash
python3 -B workflow_kit.py --json demo
```

`demo --output НОВЫЙ_ФАЙЛ.csv` сохраняет тот же принятый реестр. Занятые файлы
сохраняются; замена возможна только с явным `--replace`. Не перезаписывайте
учебные файлы и исходные данные.

## Установите команду

В POSIX-системе выберите новую отдельную папку установки и папку команд:

```bash
python3 -B install.py --prefix "$HOME/.local/share/agent-workflow-kit" --bin-dir "$HOME/.local/bin"
export PATH="$HOME/.local/bin:$PATH"
cd /tmp
agent-workflow-kit --json doctor
agent-workflow-kit --json demo --output ./meeting-tasks-demo.csv
```

Команда использует тот интерпретатор Python, которым выполнена установка.
Не удаляйте его. Если папка установки или команда заняты, выберите другие
пути. Символьные ссылки в пути отклоняются; нужны реальные папки. Свои входные
файлы и результаты храните вне папки установки.

Нативный установщик рассчитан на POSIX. В Windows запускайте исходник, например
`python workflow_kit.py ...`, подставив доступное у вас имя команды Python.
Наличие файла CI само по себе не доказывает успешный запуск на другой ОС.

Необязательная команда `agent-workflow-kit --json onboard` один раз покажет
ссылки автора и создаст локальную отметку `.onboarded`. В обычных JSON и CSV
рекламных вставок и телеметрии нет.

Для удаления из любой папки используйте те же пути:

```bash
python3 -B "$HOME/.local/share/agent-workflow-kit/uninstall.py" --prefix "$HOME/.local/share/agent-workflow-kit" --bin-dir "$HOME/.local/bin"
```

Удаление сверяет хеши принадлежащих модулю файлов и сохраняет остальные
пользовательские файлы. Изменённую или неполную установку сначала разберите,
не повторяйте удаление вслепую.

## Проверьте свои заметки

Прочитайте [порядок работы](docs/WORKFLOW.md) и
[контракт входа](docs/INPUT-CONTRACT.md):

1. Сохраните версию источника с постоянными ID встречи, строк и участников.
2. Получите от агента или оператора кандидатов на личные обязательства в точном
   JSON-формате. Не достраивайте ответственных и сроки, которых нет в основаниях.
3. Запустите `review SOURCE CANDIDATES`. Сверьте каждую строку с заметками:
   программа не отличает обещание от вопроса и не проверяет пропущенные задачи.
4. Запишите реальное решение человека по каждому кандидату. Привяжите запись
   к точным хешам источника и файла кандидатов. ID проверяющего в JSON — запись,
   а не удостоверение личности или доказательство прочтения.
5. Выполните `export SOURCE CANDIDATES DECISIONS --output NEW_FILE.csv`. Старые
   хеши проверки, отсутствующее решение или технический дефект принятого
   кандидата блокируют весь экспорт. Явно отклонённые плохие кандидаты остаются
   в счётчике отклонений и не попадают в принятый реестр.

Файл `.gitattributes` сохраняет LF при Git checkout, в том числе в Windows:
хеши учебных файлов привязаны к байтам. В своих JSON можно использовать другое
допустимое оформление, но смена окончаний строк меняет проверяемую версию.
Глобальные настройки Git для этого не нужны.

Правка байта источника, кандидата или его срока требует проверки новой версии.
Не подменяйте хеши в прежних решениях ради чистого экспорта. Позиции цитаты —
индексы Unicode code points в строке Python: от нуля, правая граница не входит.
Они отличаются от индексов UTF-16 в браузере.

CSV — локальный реестр, а не готовый контракт импорта конкретной CRM. Если
текстовая ячейка после удаления начальных пробелов начинается с `=`, `+`, `-`
или `@`, перед ней добавляется апостроф для просмотра в таблице. Счётчик
`formula_escaped_cells` показывает такие ячейки; исходный JSON не меняется.
Эта ограниченная мера меняет отображаемые ячейки и не удостоверяет безопасность
любого табличного редактора.

Сам CLI обрабатывает данные локально. Если заметки читает облачный агент,
передача данных этому сервису — отдельная граница доступа. Не помещайте
частные заметки, решения и отчёты в этот публичный пакет.

## JSON и коды завершения

Вывод — JSON; флаг `--json` можно указать явно. Unicode сохраняется через
ASCII-escape, обычный stdout использует LF. CSV сохраняется в UTF-8 с LF.
У ошибок есть `ok:false` и код, без вывода частных входных данных.

| Команда | Код 0 | Код 1 | Код 2 |
|---|---|---|---|
| `review` | Все предоставленные фрагменты технически согласованы | Полный отчёт с причинами | Некорректный вход или ошибка выполнения |
| `export` | Готовый допустимый CSV сохранён | Весь пакет заблокирован, CSV не сохранён | Ошибка входа, занятый путь или IO |
| `demo` | Учебный реестр показан или сохранён | Учебный пакет заблокирован | Ошибка выполнения |

Если человек отклонил все строки, может получиться CSV только с заголовками:
`accepted:0` и явное число отклонений. Такой исход фиксирует отклонение, а не
придуманные задачи и не отсутствие реальных обязательств. Читайте код вместе
с JSON; не скрывайте любой ненулевой исход через `|| true`.

## Дайте агенту ограниченную задачу

> Используй Agent Workflow Kit для этих разрешённых локальных заметок и файла
> кандидатов. Запусти doctor и review, сохрани код завершения и покажи все
> причины. Объясни, что подтверждает точный фрагмент, а где нужен разбор смысла
> человеком. Не придумывай ответственных, сроки, цитаты и принятие проверяющим.
> После получения файла решений проверь его привязку к точным входным версиям
> и сохрани новый CSV только при допустимом полном пакете. Верни путь, хеш,
> число принятых и отклонённых кандидатов и оставшиеся проверки. В рамках
> локального экспорта никому не пиши и не создавай задачи во внешней системе.

[Навык для агента](skills/agent-workflow-kit/SKILL.md) задаёт этот порядок для
хостов, которые умеют запускать локальный Python. Это не MCP-сервер и не
сертификат совместимости со всеми агентами.
[Company Knowledge Kit](https://github.com/ilookatshow-gif/company-knowledge-kit)
ищет буквальные основания в документах; этот пакет проверяет предложенный
реестр задач.
